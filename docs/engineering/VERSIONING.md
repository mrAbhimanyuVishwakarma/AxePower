# Centralized Versioning and Build Policy

## 1. Overview and Architecture

AxePower previously had version declarations scattered across multiple files (`AxePower.App.csproj`, `AxePower.Core.csproj`, `Installer/AxePower.iss`, `Installer/AxePowerSetup.iss`, `UpdateService.cs`, and `SettingsViewModel.cs`). This caused version drift where stale fallback constants (such as `2.0.3`) survived even after the product version had reached `2.1.0`.

To eliminate version drift and guarantee deterministic builds, AxePower establishes:
1. **Single Authoritative Source of Truth**: `Directory.Build.props` defines `<ProductVersion>2.1.0</ProductVersion>`.
2. **Synchronized Distribution**:
   - **.NET Projects**: `AxePower.App`, `AxePower.Core`, and `AxePower.Tests` automatically inherit `Version`, `AssemblyVersion`, `FileVersion`, and `InformationalVersion` from `$(ProductVersion)`.
   - **Inno Setup Installers**: Both `Installer/AxePower.iss` and `Installer/AxePowerSetup.iss` include `Installer/AppVersion.iss` which defines `#define AppVersion "<ProductVersion>"`.
   - **MSBuild Synchronization Target**: `Directory.Build.targets` ensures `Installer/AppVersion.iss` is updated automatically whenever `ProductVersion` changes.
   - **Application Runtime & Updater**: `UpdateService` resolves the runtime version from the executing product assembly, with a validated fallback (`UpdateService.FallbackVersion`) aligned with `ProductVersion`. `SettingsViewModel` and network client User-Agent headers consume this single definition.
3. **Build-Time Enforcement**:
   - MSBuild target `ValidateVersionPolicy` runs before compilation and terminates the build with a fatal error if any installer definition or passed build argument (`-p:InstallerVersion=...`) disagrees with `ProductVersion`.
   - Automated unit tests in `AxePower.Tests.VersionPolicyTests` enforce that all project files, installer scripts, and updater fallbacks match the authoritative `ProductVersion`.

## 2. Directory.Build.props Configuration

At the root of the repository, `Directory.Build.props` centrally controls:

```xml
<Project>
  <PropertyGroup>
    <!-- Single authoritative product version -->
    <ProductVersion>2.1.0</ProductVersion>
    <Version>$(ProductVersion)</Version>
    <AssemblyVersion>$(ProductVersion).0</AssemblyVersion>
    <FileVersion>$(ProductVersion).0</FileVersion>
    <InformationalVersion>$(ProductVersion)</InformationalVersion>

    <!-- Shared product metadata -->
    <Authors>Abhimanyu Vishwakarma</Authors>
    <Company>AxePower</Company>
    <Product>AxePower</Product>
    <Copyright>Copyright © 2026 Abhimanyu Vishwakarma</Copyright>

    <!-- Language, runtime, and build determinism -->
    <LangVersion>12.0</LangVersion>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
    <Deterministic>true</Deterministic>

    <!-- Code analysis policy -->
    <EnableNETAnalyzers>true</EnableNETAnalyzers>
    <AnalysisMode>Default</AnalysisMode>
  </PropertyGroup>
</Project>
```

## 3. Installer Synchronization and Validation

### Installer/AppVersion.iss
Automatically maintained by MSBuild (`Directory.Build.targets`):
```iss
; Auto-generated by MSBuild from Directory.Build.props - DO NOT EDIT MANUALLY
#define AppVersion "2.1.0"
```

### Inno Setup Scripts
- `Installer/AxePower.iss` includes `AppVersion.iss`:
  ```iss
  #define AppName "AxePower"
  #include "AppVersion.iss"
  ...
  AppVersion={#AppVersion}
  OutputBaseFilename=AxePower-v{#AppVersion}-Setup
  ```
- `Installer/AxePowerSetup.iss` includes `AppVersion.iss`:
  ```iss
  #include "AppVersion.iss"
  [Setup]
  AppName=AxePower
  AppVersion={#AppVersion}
  OutputBaseFilename=AxePower-v{#AppVersion}-Setup
  ```

### Build-Time Validation Target (`Directory.Build.targets`)
If an installer script hardcodes an out-of-sync version or a build parameter is passed such as `dotnet build -p:InstallerVersion=9.9.9`, MSBuild halts:
```
error : Version mismatch detected! Directory.Build.props specifies ProductVersion '2.1.0', but Installer version is '9.9.9'.
```

## 4. Exact Version-Bump Procedure

To increment the product version (e.g., from `2.1.0` to `2.1.1` or `2.2.0`):

1. **Update `Directory.Build.props`**:
   Change `<ProductVersion>`:
   ```xml
   <ProductVersion>2.2.0</ProductVersion>
   ```

2. **Update `UpdateService.cs` Fallback Constant**:
   In `AxePower.Core/Services/UpdateService.cs`, update:
   ```csharp
   public const string FallbackVersion = "2.2.0";
   ```

3. **Build the Solution**:
   Run:
   ```powershell
   dotnet build AxePower.sln -c Release
   ```
   *Note: MSBuild will automatically sync `Installer/AppVersion.iss` to `#define AppVersion "2.2.0"` and validate version agreement across all targets.*

4. **Run Unit Tests**:
   Run:
   ```powershell
   dotnet test AxePower.Tests/AxePower.Tests.csproj -c Release
   ```
   *The test suite executes `VersionPolicyTests` to verify that `Directory.Build.props`, assemblies, installer scripts, and updater fallbacks match.*

5. **Update Release Documentation** (for public releases):
   Update version badges and highlights in `README.md` and `RELEASE_README.md`.

6. **Publish and Build Installer**:
   ```powershell
   dotnet publish AxePower.App/AxePower.App.csproj -c Release -r win-x64 --self-contained false -p:PublishSingleFile=false
   & "C:\Program Files (x86)\Inno Setup 6\ISCC.exe" "Installer\AxePower.iss"
   ```
   This generates `Installer/Output/AxePower-v2.2.0-Setup.exe`.

---

## 5. Deliberate Mismatch Verification

To verify that accidental or malicious version drift is prevented:
```powershell
# Attempting to build with a conflicting installer version parameter fails immediately:
dotnet build AxePower.sln -c Release -p:InstallerVersion=9.9.9
```
Output:
```
error : Version mismatch detected! Directory.Build.props specifies ProductVersion '2.1.0', but Installer version is '9.9.9'.
Build FAILED.
```
