# Working on AxePower

- The maintainer designated `windowsupdatepage-rework` for v2.1.5. At the start of an update, read [WORK_LOG.md](WORK_LOG.md) and check `git status --short --branch`, `git log -1 --oneline`, and the version in [Directory.Build.props](Directory.Build.props). Preserve local edits and use the maintainer's latest source branch. Ask the maintainer if the intended branch or release version is ambiguous.
- Use [global.json](global.json) for the .NET SDK. Start from the repository root in PowerShell. Run `powershell -ExecutionPolicy Bypass -File scripts\run-latest.ps1` to build and open the current checkout. It prints the branch, commit, and executable version. If AxePower is already running, exit through its tray before launching the checkout build.
- Use [CONTRIBUTING.md](CONTRIBUTING.md) for locked restore and checks, the [WPF engineering skill](.agents/plugins/axepower-wpf/skills/axepower-wpf-engineer/SKILL.md) for UI and Windows integration, and [skillsMD](skillsMD/README.md) for feature guidance. Update [the Music and LAN portal ledger](skillsMD/MUSIC_FIX_PLAN.md) when work touches those areas.
- Follow [the release pipeline](docs/engineering/RELEASE_PIPELINE.md) to build Setup from a fresh x64 publish output. Put a local installer copy in `Installer/Output/`. Record the version, branch, checks, and any handoff details in [WORK_LOG.md](WORK_LOG.md) after packaging. Keep local artifacts and reference repositories out of commits.
